Question 268 / 284

You have an application deployed on Cloud Run with users around the world. You need to configure Cloud Run to route all users to their nearest region so that request responses have low latency. What should you do?

  • A. Deploy the application to any one region, and serve the application at a global anycast IP address behind a global external Application Load Balancer.
  • B. Deploy the application to each region, and serve the application at a global anycast IP address behind a global external Application Load Balancer.
  • C. Deploy the application to one region per continent and serve the application by using a regional external Application Load Balancer in each region. Attach the same global IP address to all the regional load balancers.
  • D. Deploy the application to any one region, and configure Google Cloud Armor in the frontend to allow traffic from all IP addresses.
Show Suggested Answer
Suggested Answer: B 
Odpowiedź: B

Wyjaśnienie:
Aby uzyskać niskie opóźnienia dla użytkowników globalnych, aplikacja musi być wdrożona blisko użytkowników (czyli w wielu regionach). Globalny zewnętrzny Application Load Balancer (GCLB) z jednym globalnym adresem IP (anycast) automatycznie kieruje ruch użytkowników do najbliższego zdrowego backendu (w tym przypadku Cloud Run w odpowiednim regionie).

Wyjaśnienie błędnych odpowiedzi:
- A: Wdrożenie w jednym regionie nie zapewnia niskiego opóźnienia dla użytkowników z całego świata.
- C: Regionalne Load Balancery nie obsługują globalnego routingu w ten sposób; nie można przypisać tego samego globalnego IP do wielu regionalnych LB.
- D: Google Cloud Armor służy do ochrony (WAF), a nie do routingu globalnego.

Analiza i Podsumowanie Dyskusji (AI)

Low latency globally = Multi-region deployment + Global Load Balancer.

💡 Wskazówki i Triki (Exam Tips)

  • Cloud Run global routing = Global External HTTP(S) Load Balancer.

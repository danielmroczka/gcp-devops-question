Question 106 / 201

You are implementing a CI/CD pipeline for your application in your company's multi-cloud environment. Your application is deployed by using custom Compute Engine images and the equivalent in other cloud providers. You need to implement a solution that will enable you to build and deploy the images to your current environment and is adaptable to future changes. Which solution stack should you use?

  • A. Cloud Build with Packer
  • B. Cloud Build with Google Cloud Deploy
  • C. Google Kubernetes Engine with Google Cloud Deploy
  • D. Cloud Build with kpt
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
1. Packer jest narzędziem typu "infrastructure as code" służącym do tworzenia identycznych obrazów maszyn wirtualnych dla wielu platform chmurowych (multi-cloud).
2. Cloud Build to usługa CI/CD, która może wyzwalać procesy budowania tych obrazów przy użyciu Packera. To połączenie idealnie spełnia wymagania dotyczące budowania i wdrażania obrazów w środowiskach multi-cloud.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja B: Google Cloud Deploy służy głównie do ciągłego wdrażania aplikacji na GKE, Cloud Run lub GCE, ale nie jest narzędziem do budowania (tworzenia) obrazów maszyn wirtualnych.
- Opcja C: GKE jest rozwiązaniem kontenerowym, a nie służy do zarządzania obrazami Compute Engine (VM).
- Opcja D: kpt to narzędzie do zarządzania konfiguracją Kubernetes, nie służy do budowania obrazów maszyn wirtualnych.

Analiza i Podsumowanie Dyskusji (AI)

Jeśli widzisz w pytaniu "multi-cloud" oraz "Compute Engine images" (obrazy VM), Twoim "go-to" rozwiązaniem jest Packer.

💡 Wskazówki i Triki (Exam Tips)

  • Packer = obrazy (VM). Jeśli pytanie mówi o budowaniu obrazów VM dla różnych chmur (multi-cloud), Packer jest standardem przemysłowym.
  • Cloud Deploy = wdrażanie (deploy) głównie aplikacji (kontenerów), a nie budowanie obrazów VM.

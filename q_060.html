Question 60 / 201

You have migrated an e-commerce application to Google Cloud Platform (GCP). You want to prepare the application for the upcoming busy season.

What should you do first to prepare for the busy season?

  • A. Load test the application to profile its performance for scaling.
  • B. Enable AutoScaling on the production clusters, in case there is growth.
  • C. Pre-provision double the compute power used last season, expecting growth.
  • D. Create a runbook on inflating the disaster recovery (DR) environment if there is growth.
Show Suggested Answer
Suggested Answer: A 
Poprawna odpowiedź: A. Load test the application to profile its performance for scaling.

Wyjaśnienie:
Przed zbliżającym się okresem wzmożonego ruchu (np. Black Friday), pierwszym i najważniejszym krokiem jest zrozumienie granic wydajnościowych systemu. Testy obciążeniowe (Load Testing) pozwalają na: 1. Zidentyfikowanie wąskich gardeł (np. limity bazy danych, zbyt mała pula połączeń), 2. Wyznaczenie metryk, według których system powinien się skalować, 3. Zweryfikowanie, czy aplikacja jest bezstanowa i faktycznie potrafi się skalować horyzontalnie. Bez profilowania wydajności, automatyczne skalowanie może nie zadziałać poprawnie lub nastąpić zbyt późno.

Dlaczego inne odpowiedzi są błędne:
- B: Enable AutoScaling on the production clusters: Włączenie AutoSkalowania bez wcześniejszych testów jest ryzykowne. Musisz wiedzieć, kiedy skalować (np. przy 70% CPU czy 500ms latencji?) i jak szybko nowe instancje są gotowe do pracy. Testy obciążeniowe dostarczają danych niezbędnych do poprawnej konfiguracji AutoSkalowania.
- C: Pre-provision double the compute power: "Rzucanie zasobami" w problem jest nieefektywne kosztowo i nie gwarantuje sukcesu. Jeśli wąskim gardłem jest baza danych (pojedynczy punkt awarii), podwojenie liczby serwerów aplikacyjnych może wręcz dobić bazę danych jeszcze szybciej.
- D: Create a runbook on inflating the DR environment: Środowisko Disaster Recovery służy do przywracania usług po awarii, a nie do obsługi planowanego wzrostu ruchu. Obsługa ruchu powinna odbywać się w środowisku produkcyjnym poprzez skalowanie horyzontalne.

Hity i triki (GCP DevOps Exam):
- Load Testing Tools on GCP: Rozważ użycie narzędzi takich jak Locust (często spotykany w dokumentacji GCP), JMeter lub k6.
- Bottleneck identification: Pamiętaj, że skalowanie Compute Engine to nie wszystko – sprawdź limity Cloud SQL (IOPS), limity API oraz limity sieciowe (bandwidth).
- Warm-up: Niektóre usługi potrzebują czasu na "rozgrzanie" (np. Load Balancer przy ekstremalnie szybkich skokach ruchu). W takich przypadkach warto zgłosić planowany szczyt do wsparcia Google (dla klientów Premium Support).

Analiza i Podsumowanie (GCP DevOps Expert)

Przygotowanie na "busy season" to proces ciągły, który zaczyna się od pomiarów. W chmurze nie pytamy "czy" się wyskalujemy, ale "jak efektywnie" to zrobimy.

💡 Kluczowe wnioski:

  • Capacity Planning: Wykorzystaj dane historyczne z Cloud Monitoring, aby oszacować przewidywany ruch, ale zawsze zweryfikuj to testami.
  • Horizontal Pod Autoscaler (HPA): Jeśli używasz GKE, upewnij się, że Twoje limity i żądania (requests/limits) są poprawnie ustawione na podstawie wyników testów.
  • Quotas: Sprawdź limity projektu (Quotas) w konsoli GCP. Nic tak nie psuje Black Friday jak brak możliwości uruchomienia nowych VM ze względu na limit CPU w regionie.

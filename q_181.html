Question 181 / 201

SLO

You manage a critical API running on Cloud Run that serves an average of 10,000 requests per minute. You need to define service level objectives (SLOs) for availability and latency to ensure that the API meets user expectations, which include 99.9% availability and a maximum latency of 200 milliseconds for 95% of requests. You also need to ensure these SLOs are actively monitored and measured. What should you do?

  • A. Configure Cloud Monitoring to send alerts when average API latency exceeds 150 ms or the error rate surpasses 0.1%.
  • B. Prioritize latency as the only SLO, targeting 100 ms for 99% of requests.
  • C. Set SLOs for 99% availability at 99% and 500 ms latency for 90% of requests. Use Cloud Monitoring to track SLOs and alert on violations.
  • D. Set SLOs for the API by using availability and latency service level indicators. Use Cloud Monitoring to track SLOs and alert on violations.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
Pytanie dotyczy zarządzania poziomami usług (SLO) w GCP.
1. Opcja D jest poprawna, ponieważ w Google Cloud Monitoring SLO definiuje się poprzez SLI (Service Level Indicators) – dla dostępności (Availability) i opóźnień (Latency). Cloud Monitoring udostępnia dedykowane narzędzia do definiowania takich SLO i automatycznego alertowania na podstawie tzw. "burn rate" (szybkość zużycia budżetu błędów).

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Alertowanie na podstawie sztywnych wartości (np. "latency > 150ms") to tradycyjne monitorowanie (alerting), a nie podejście oparte na SLO (Service Level Objectives). SLO skupia się na budżetach błędów w dłuższym czasie.
- Opcja B: Arbitralne narzucenie innych celów niż wymagane w pytaniu (100ms vs 200ms) jest błędne – cele muszą odpowiadać wymaganiom biznesowym/użytkowników.
- Opcja C: Podobnie jak w opcji B, wartości SLO są inne niż wymagane w pytaniu. SLO musi odzwierciedlać realne potrzeby.

Analiza i Podsumowanie Dyskusji (AI)

W GCP, gdy słyszysz "monitorować i mierzyć SLO", odpowiedzią jest zawsze użycie dedykowanej funkcji Service Monitoring w Cloud Monitoring, która opiera się na SLI (np. dostępność lub opóźnienia).

💡 Wskazówki i Triki (Exam Tips)

  • SLO vs Alert: Jeśli w pytaniu mowa o SLO, zawsze wybieraj odpowiedź używającą terminów SLI/SLO wewnątrz narzędzi zarządzanych (Cloud Monitoring), a nie zwykłe alerty oparte na progach (thresholds).
  • Zgodność z pytaniem: Zawsze sprawdzaj, czy liczby w odpowiedzi (np. 99%, 500ms) zgadzają się z wymaganiami w treści pytania.

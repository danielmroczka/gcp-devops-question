Question 95 / 201

GKE Kubernetes Logging

Your team deploys applications to three Google Kubernetes Engine (GKE) environments: development, staging, and production. You use GitHub repositories as your source of truth. You need to ensure that the three environments are consistent. You want to follow Google-recommended practices to enforce and install network policies and a logging DaemonSet on all the GKE clusters in those environments.

What should you do?

  • A. Use Google Cloud Deploy to deploy the network policies and the DaemonSet. Use Cloud Monitoring to trigger an alert if the network policies and DaemonSet drift from your source in the repository.
  • B. Use Google Cloud Deploy to deploy the DaemonSet and use Policy Controller to configure the network policies. Use Cloud Monitoring to detect drifts from the source in the repository and Cloud Functions to correct the drifts.
  • C. Use Cloud Build to render and deploy the network policies and the DaemonSet. Set up Config Sync to sync the configurations for the three environments.
  • D. Use Cloud Build to render and deploy the network policies and the DaemonSet. Set up a Policy Controller to enforce the configurations for the three environments.
Show Suggested Answer
Suggested Answer: C 
Odpowiedź: C

Wyjaśnienie:
To pytanie dotyczy utrzymania spójności konfiguracji w wielu klastrach GKE przy użyciu podejścia GitOps.

1. Config Sync: Jest to kluczowe narzędzie Google Cloud do wdrażania GitOps. Pozwala ono na synchronizację zasobów Kubernetes (takich jak NetworkPolicies czy DaemonSets) z repozytorium Git (source of truth) do wielu klastrów. Config Sync nie tylko instaluje zasoby, ale także monitoruje ich stan i automatycznie naprawia wszelkie niezamierzone zmiany ("drift"), co zapewnia spójność środowisk.
2. Instalacja vs Wymuszanie: Pytanie prosi o "enforce and install". Config Sync instaluje faktyczne obiekty (np. logging DaemonSet), podczas gdy Policy Controller (oparty na OPA Gatekeeper) służy głównie do sprawdzania zgodności z regułami (np. "każdy pod musi mieć etykietę"), ale sam nie instaluje aplikacji ani infrastruktury pomocniczej z repozytorium.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A i B: Google Cloud Deploy jest świetnym narzędziem do progresywnego wdrażania aplikacji, ale Config Sync jest bardziej naturalnym wyborem dla stałej synchronizacji polityk sieciowych i infrastrukturalnych zasobów klastra w modelu GitOps.
- Opcja D: Policy Controller jest komplementarny do Config Sync, ale sam w sobie nie służy do "instalowania" zasobów takich jak DaemonSet z repozytorium GitHub.

💡 Wskazówki i Triki (Exam Tips)

  • Config Sync: Synchronizacja "żywych" obiektów (Deployments, Services, NetworkPolicies) z Gitem. Słowa klucze: Consistency, GitOps, Source of Truth.
  • Policy Controller: Sprawdzanie poprawności (Compliance/Governance). Słowa klucze: Enforce policies, Guardrails, Admission Control.
  • Jeśli pytanie mówi o utrzymaniu spójności infrastruktury (np. DaemonSet) w wielu klastrach, szukaj Config Sync.

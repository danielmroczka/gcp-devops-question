Question 152 / 201

GKE Kubernetes Terraform

You are designing a system with three different environments: development, quality assurance (QA), and production. Each environment will be deployed with Terraform and has a Google Kubernetes Engine (GKE) cluster created so that application teams can deploy their applications. Anthos Config Management will be used and templated to deploy infrastructure level resources in each GKE cluster. All users (for example, infrastructure operators and application owner

  • will use GitOps.


How should you structure your source control repositories for both Infrastructure as Code (IaC) and application code?

  • A. • Cloud Infrastructure (Terraform) repository is shared: different directories are different environments
  • B. • Cloud Infrastructure (Terraform) repository is shared: different directories are different environments
  • C. • Cloud Infrastructure (Terraform) repository is shared: different branches are different environments
  • D. • Cloud Infrastructure (Terraform) repositories are separated: different branches are different environments
Show Suggested Answer
Suggested Answer: A 

Odpowiedź: A

Wyjaśnienie:
W GitOps, dla Infrastructure as Code (IaC) przy użyciu Terraform, zaleca się stosowanie pojedynczego repozytorium z odpowiednią strukturą katalogów, aby zarządzać różnymi środowiskami.

Dlaczego odpowiedź A jest poprawna:
- Struktura katalogów: Pozwala na łatwe współdzielenie modułów Terraform między środowiskami (DRY - Don't Repeat Yourself), przy zachowaniu izolacji zmiennych dla każdego z nich (dev/qa/prod). Jest to przejrzyste i łatwe do zarządzania w systemach CI/CD.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja C i D: Używanie różnych gałęzi (branches) dla różnych środowisk jest często odradzane w GitOps. Powoduje to trudności w śledzeniu zmian (git merge/rebase między gałęziami), sprawia, że porównywanie konfiguracji między środowiskami jest skomplikowane i sprzyja powstawaniu "config driftu".
- Opcja B: Jest identyczna z A (błąd w pytaniu), jednak A jest zazwyczaj poprawną odpowiedzią wskazującą na strukturę katalogową.

Analiza i Podsumowanie Dyskusji (AI)

W pytaniach o strukturę repozytoriów Terraform/GitOps dla wielu środowisk: Katalogi > Gałęzie.

💡 Wskazówki i Triki (Exam Tips)

  • Unikaj Branching Environments: Zarządzanie środowiskami za pomocą gałęzi (branches) w Git jest anty-wzorcem w nowoczesnym DevOps i GitOps.
  • DRY: Używaj modułów Terraform do współdzielenia logiki i struktur katalogów do definiowania wartości dla środowisk.

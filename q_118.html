Question 118 / 201

Logging

You are building and running client applications in Cloud Run and Cloud Functions. Your client requires that all logs must be available for one year so that the client can import the logs into their logging service. You must minimize required code changes.

What should you do?

  • A. Update all images in Cloud Run and all functions in Cloud Functions to send logs to both Cloud Logging and the client's logging service. Ensure that all the ports required to send logs are open in the VPC firewall.
  • B. Create a Pub/Sub topic, subscription, and logging sink. Configure the logging sink to send all logs into the topic. Give your client access to the topic to retrieve the logs.
  • C. Create a storage bucket and appropriate VPC firewall rules. Update all images in Cloud Run and all functions in Cloud Functions to send logs to a file within the storage bucket.
  • D. Create a logs bucket and logging sink. Set the retention on the logs bucket to 365 days. Configure the logging sink to send logs to the bucket. Give your client access to the bucket to retrieve the logs.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
Pytanie dotyczy długoterminowego przechowywania logów z zachowaniem minimalnej liczby zmian w kodzie.
1. Logging Sink (Sink logowania) pozwala automatycznie przekierowywać logi do różnych miejsc (m.in. Cloud Storage, BigQuery, Pub/Sub).
2. Logs Bucket (Wiadro logów) to specjalny typ zasobnika w Cloud Logging, który pozwala na ustawienie retencji (np. 365 dni) i zarządzanie logami w sposób natywny.
3. Minimalizacja zmian w kodzie: Rozwiązanie to wykorzystuje infrastrukturę GCP (sinki i buckety), dzięki czemu kod aplikacji nie musi być modyfikowany, aby wysyłać logi do zewnętrznego serwisu.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Wymaga modyfikacji wszystkich aplikacji (send logs to both...), co jest sprzeczne z wymaganiem "minimalizacji zmian w kodzie" i wprowadza ogromny dług techniczny.
- Opcja B: Pub/Sub jest systemem kolejkowania komunikatów, a nie długoterminowego składowania logów (retencja w Pub/Sub jest zazwyczaj znacznie krótsza niż rok).
- Opcja C: Ręczne wysyłanie logów z kontenerów/funkcji do storage bucketa jest bardzo trudne do utrzymania, wymaga zmian w kodzie i skomplikowanej konfiguracji firewalli/uprawnień, co jest niezalecane.

Więcej informacji:

- Google Cloud: Logs Buckets

Analiza i Podsumowanie Dyskusji (AI)

Kluczem w tym pytaniu jest minimalizacja zmian w kodzie. W GCP, jeśli musisz przesłać logi w inne miejsce, zawsze szukaj rozwiązania opartego na Logging Sinks, a nie na zmianach wewnątrz aplikacji.

💡 Wskazówki i Triki (Exam Tips)

  • Zasada GCP: Jeśli możesz skonfigurować to na poziomie infrastruktury (Logging Sink), nie dotykaj kodu aplikacji.
  • Logging Sinks: To Twój najlepszy przyjaciel w pytaniach o przekierowywanie logów.

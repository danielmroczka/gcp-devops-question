Question 155 / 201

Cloud Build Terraform

You are deploying a Cloud Build job that deploys Terraform code when a Git branch is updated. While testing, you noticed that the job fails. You see the following error in the build logs: Initializing the backend... Error: Failed to get existing workspaces: querying Cloud Storage failed: googleapi: Error 403 You need to resolve the issue by following Google-recommended practices.

What should you do?

  • A. Change the Terraform code to use local state.
  • B. Create a storage bucket with the name specified in the Terraform configuration.
  • C. Grant the roles/owner Identity and Access Management (IAM) role to the Cloud Build service account on the project.
  • D. Grant the roles/storage.objectAdmin Identity and Access Management (1AM) role to the Cloud Build service account on the state file bucket.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
Błąd 403 (Forbidden) podczas uzyskiwania dostępu do backendu Terraform w Cloud Storage oznacza, że konto usługi (Cloud Build Service Account), które wykonuje build, nie posiada wystarczających uprawnień do odczytu/zapisu pliku stanu (state file) w bucketcie.
- Opcja D (Grant roles/storage.objectAdmin): Jest to zgodne z zasadą minimalnych uprawnień (Least Privilege Principle). Konto Cloud Build potrzebuje dostępu do obiektu (pliku stanu), a rola Storage Object Admin jest odpowiednia do operacji na plikach (backend Terraform).
- Opcja A: Użycie lokalnego stanu w CI/CD jest niepoprawne (stan musi być współdzielony).
- Opcja B: Błąd 403 dotyczy uprawnień, a nie braku bucketa (gdyby bucket nie istniał, byłby błąd 404).
- Opcja C: Rola "Owner" daje zbyt szerokie uprawnienia (narusza zasadę Least Privilege).

Analiza i Podsumowanie Dyskusji (AI)

Kiedy widzisz "403" w kontekście usług GCP i CI/CD, zawsze szukaj odpowiedzi z "Least Privilege" (najmniejsze wymagane uprawnienia).

💡 Wskazówki i Triki (Exam Tips)

  • Unikaj roli "Owner": Nigdy nie używaj "Owner" na egzaminie, jeśli istnieje bardziej precyzyjna rola.
  • Storage Object Admin: To standardowa rola do zarządzania stanem Terraform w bucketach GCS.

Question 129 / 201

You need to deploy a new service to production. The service needs to automatically scale using a managed instance group and should be deployed across multiple regions. The service needs a large number of resources for each instance and you need to plan for capacity. What should you do?

  • A. Monitor results of Cloud Trace to determine the optimal sizing.
  • B. Use the n2-highcpu-96 machine type in the configuration of the managed instance group.
  • C. Deploy the service in multiple regions and use an internal load balancer to route traffic.
  • D. Validate that the resource requirements are within the available project quota limits of each region.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
- Quotas (limity) w GCP są kluczowym elementem planowania pojemności. Gdy wdrażasz usługę wymagającą dużej ilości zasobów (duże instancje) w wielu regionach za pomocą Managed Instance Groups (MIGs), musisz upewnić się, że Twój projekt posiada wystarczający limit (quota) dla tych zasobów w każdym docelowym regionie, aby autoscale mógł poprawnie działać.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Cloud Trace służy do monitorowania wydajności (latencji) aplikacji, a nie do planowania capacity dla infrastruktury pod autoscaling.
- Opcja B: Wybór konkretnego typu maszyny (np. n2-highcpu-96) jest decyzją konfiguracyjną, ale nie rozwiązuje problemu "planowania capacity" w wielu regionach, jeśli nie sprawdzisz dostępności limitów dla tych maszyn w danym regionie.
- Opcja C: Wdrażanie w wielu regionach i używanie load balancera to poprawna architektura, ale nie adresuje wprost wymogu "planowania dla capacity" i ryzyka niepowodzenia wdrożenia z powodu braku limitów.

Więcej informacji:
- GCP Compute Engine: Quotas

Analiza i Podsumowanie Dyskusji (AI)

Kluczowe słowo w pytaniach o skalowanie i wdrażanie: Capacity Planning i Quotas. Zawsze sprawdzaj limity (quotas) w każdym regionie, w którym planujesz wdrożenie.

💡 Wskazówki i Triki (Exam Tips)

  • Złota zasada: Zawsze zanim skalujesz infrastrukturę, sprawdź dostępność limitów (Quotas) w regionach docelowych. Unikniesz w ten sposób błędu QUOTA_EXCEEDED podczas automatycznego skalowania (autoscaling).

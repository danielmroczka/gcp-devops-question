Question 10 / 201

You have a pool of application servers running on Compute Engine. You need to provide a secure solution that requires the least amount of configuration and allows developers to easily access application logs for troubleshooting. How would you implement the solution on GCP?

  • A. Deploy the Stackdriver logging agent to the application servers. Give the developers the IAM Logs Viewer role to access Stackdriver and view logs.
  • B. Deploy the Stackdriver logging agent to the application servers. Give the developers the IAM Logs Private Logs Viewer role to access Stackdriver and view logs.
  • C. Deploy the Stackdriver monitoring agent to the application servers. Give the developers the IAM Monitoring Viewer role to access Stackdriver and view metrics.
  • D. Install the gsutil command line tool on your application servers. Write a script using gsutil to upload your application log to a Cloud Storage bucket, and then schedule it to run via cron every 5 minutes. Give the developers the IAM Object Viewer access to view the logs in the specified bucket.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A.

Wyjaśnienie:
Stackdriver Logging agent (obecnie Cloud Logging agent) jest natywnym rozwiązaniem GCP do zbierania logów z maszyn wirtualnych. Instalacja agenta na maszynach w połączeniu z rolą IAM "Logs Viewer" zapewnia deweloperom bezpieczny, scentralizowany i łatwy dostęp do logów w konsoli GCP, przy minimalnym nakładzie pracy konfiguracyjnej (least effort).

B. Rola "Private Logs Viewer" służy do przeglądania logów zawierających dane wrażliwe (PII) lub logów audytowych o podwyższonym rygorze dostępu. Zgodnie z zasadą Least Privilege, nie należy jej nadawać, jeśli wystarczy zwykły "Logs Viewer".
C. Monitoring agent służy do zbierania metryk (CPU, RAM), a nie logów aplikacji.
D. Ręczne pisanie skryptów do uploadu logów do GCS (cron + gsutil) to tzw. "antywzorzec" (antipattern) w GCP – wymaga ogromnego nakładu pracy w utrzymaniu, tworzy problemy z wydajnością, opóźnieniami w dostępności logów i jest bardzo trudne w debugowaniu. Zawsze wybieraj managed services (Logging agent).

Analiza i Podsumowanie Dyskusji (AI)

Kluczem jest "least amount of configuration" (najmniej pracy) i "secure solution". Zarządzane usługi (Managed Services) jak Cloud Logging zawsze wygrywają z pisaniem własnych skryptów (np. cron+gsutil).

Question 183 / 201

Cloud Build Artifact Registry

You use Artifact Registry to store container images built with Cloud Build. You need to ensure that all existing and new images are continuously scanned for vulnerabilities. You also want to track who pushed each image to the registry.

What should you do?

  • A. Configure Artifact Registry to automatically scan new images and periodically re-scan all images. Use Cloud Audit Logs to track image uploads and identify the user who pushed each image.
  • B. Configure Artifact Registry to send vulnerability scan results to a Cloud Storage bucket. Use a separate script to parse results and notify a security team.
  • C. Configure Artifact Registry to automatically re-scan images daily. Enable Cloud Audit Logs to track these scans, and use Logs Explorer to identify vulnerabilities.
  • D. Configure Artifact Registry to automatically trigger vulnerability scans for new image tags, and view scan results. Use Cloud Audit Logs to track image tag creation events.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
Pytanie dotyczy bezpieczeństwa obrazów w Artifact Registry.
1. Artifact Registry posiada wbudowaną integrację ze skanerem podatności (Artifact Analysis), który pozwala na automatyczne skanowanie obrazów przy przesłaniu (push) oraz opcjonalnie na okresowe (re-scanning) w poszukiwaniu nowych luk.
2. Cloud Audit Logs (Data Access logs) przechowują szczegółowe informacje o tym, kto (które konto IAM) wykonał operację zapisu (push) obrazu do registry.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja B: Jest to podejście niepotrzebnie skomplikowane ("toil"). GCP zapewnia natywne narzędzia do skanowania i raportowania, nie ma potrzeby budowania własnych parserów.
- Opcja C: Logs Explorer nie służy do "identyfikacji podatności" (vulnerabilities), służy do przeglądania logów. Podatności przegląda się w sekcji Security w Artifact Registry / Artifact Analysis.
- Opcja D: Skanowanie nowych tagów to tylko część zadania. Ponadto Audit Logs służą do śledzenia aktywności użytkowników, a nie do przeglądania wyników skanowania podatności.

Więcej informacji:
- Google Cloud: Scanning images for vulnerabilities
- Google Cloud: Audit Logging

Analiza i Podsumowanie Dyskusji (AI)

W GCP, gdy potrzebujesz "śledzić, kto co zrobił", zawsze szukasz odpowiedzi z Cloud Audit Logs. Gdy potrzebujesz "skanować podatności w registry", zawsze szukasz Artifact Analysis (wbudowane w Artifact Registry).

💡 Wskazówki i Triki (Exam Tips)

  • Zawsze natywnie: GCP oferuje gotowe usługi do większości zadań DevOps. Nie pisz własnych skryptów ("custom scripts"), jeśli istnieje usługa Managed.
  • Skanowanie: Pamiętaj, że skanowanie podatności w GCP to Artifact Analysis.

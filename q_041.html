Question 41 / 201

You support a high-traffic web application that runs on Google Cloud Platform (GCP). You need to measure application reliability from a user perspective without making any engineering changes to it. What should you do? (Choose two.)

  • A. Review current application metrics and add new ones as needed.
  • B. Modify the code to capture additional information for user interaction.
  • C. Analyze the web proxy logs only and capture response time of each request.
  • D. Create new synthetic clients to simulate a user journey using the application.
  • E. Use current and historic Request Logs to trace customer interaction with the application.
Show Suggested Answer
Suggested Answer: DE 
Odpowiedź: DE.

Wyjaśnienie:
Poprawnymi odpowiedziami są D i E:
- D (Create new synthetic clients to simulate a user journey): Syntetyczne testy pozwalają na monitorowanie dostępności i wydajności aplikacji z perspektywy użytkownika (tzw. "Black-box monitoring") bez konieczności wprowadzania zmian w kodzie źródłowym samej aplikacji.
- E (Use current and historic Request Logs to trace customer interaction): Request Logs (dostępne w Google Cloud Logging) pozwalają na analizę zachowania użytkowników, czasów odpowiedzi i błędów (HTTP status codes) na poziomie infrastruktury (np. poprzez HTTP Load Balancer), co również nie wymaga zmian w aplikacji.

Analiza niepoprawnych odpowiedzi:
- A: "Review current application metrics and add new ones as needed" sugeruje konieczność dodawania metryk, co zazwyczaj wiąże się z instrumentacją kodu (zmiany w aplikacji), czego pytanie zabrania ("without making any engineering changes").
- B: "Modify the code to capture additional information" bezpośrednio narusza wymaganie braku zmian w kodzie aplikacji.
- C: "Analyze the web proxy logs only..." jest zbyt wąskie. Samo analizowanie logów proxy może nie dawać pełnego obrazu "user journey" w porównaniu do syntetyków, a skupienie się *tylko* na jednym źródle jest ograniczeniem.

Wskazówki (Hints & Tricks):
- SRE (Site Reliability Engineering) często korzysta z tzw. "Black-box monitoring", aby mierzyć SLI (Service Level Indicators) z perspektywy klienta końcowego.
- Jeśli pytanie zabrania zmian w kodzie, zawsze szukaj metod opartych na logach infrastrukturalnych (Cloud Logging), monitorowaniu sieciowym lub syntetycznych testach (Uptime Checks / Synthetic Monitoring w Cloud Monitoring).

Przydatne linki:
- https://cloud.google.com/monitoring/uptime-checks
- https://cloud.google.com/logging/docs/load-balancing

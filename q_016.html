Question 16 / 201

GKE Kubernetes

You are managing the production deployment to a set of Google Kubernetes Engine (GKE) clusters. You want to make sure only images which are successfully built by your trusted CI/CD pipeline are deployed to production.

What should you do?

  • A. Enable Cloud Security Scanner on the clusters.
  • B. Enable Vulnerability Analysis on the Container Registry.
  • C. Set up the Kubernetes Engine clusters as private clusters.
  • D. Set up the Kubernetes Engine clusters with Binary Authorization.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D.

Wyjaśnienie:
Poprawną odpowiedzią jest **D (Set up the Kubernetes Engine clusters with Binary Authorization)**.

**Dlaczego D jest poprawne?**
Binary Authorization to usługa bezpieczeństwa w Google Cloud, która działa jako kontroler przyjęć (admission controller) dla Google Kubernetes Engine (GKE). Pozwala ona na wymuszenie polityki, zgodnie z którą tylko zaufane i zweryfikowane obrazy kontenerów mogą być wdrażane w klastrze. W typowym przepływie CI/CD, Twój pipeline (np. Cloud Build) buduje obraz, przeprowadza testy i skanowanie podatności, a następnie tworzy "atest" (cyfrowy podpis). Binary Authorization sprawdza te atesty przed zezwoleniem na uruchomienie kontenera, co gwarantuje, że tylko obrazy z Twojego zaufanego potoku trafią na produkcję.

**Dlaczego pozostałe opcje są błędne?**
*   **A. Enable Cloud Security Scanner on the clusters:** Cloud Security Scanner służy do wykrywania typowych luk w zabezpieczeniach aplikacji internetowych (np. XSS, SQL Injection) działających na App Engine, Compute Engine lub GKE. Nie zajmuje się weryfikacją pochodzenia obrazów ani autoryzacją wdrożeń.
*   **B. Enable Vulnerability Analysis on the Container Registry:** To ważna funkcja (część Container Analysis), która skanuje obrazy pod kątem znanych podatności (CVE). Jednak samo skanowanie jedynie dostarcza informacji o bezpieczeństwie obrazu – nie blokuje automatycznie wdrożenia nieautoryzowanego obrazu, chyba że zostanie to zintegrowane z Binary Authorization jako reguła polityki.
*   **C. Set up the Kubernetes Engine clusters as private clusters:** Klastry prywatne izolują węzły od publicznego Internetu, nadając im tylko wewnętrzne adresy IP. Zwiększa to bezpieczeństwo sieciowe, ale nie kontroluje tego, czy dany obraz kontenera jest zaufany, czy nie.

### 💡 Hity i triki (Hints & Tricks)
- Słowa kluczowe: **"trusted images"**, **"only images built by..."**, **"verify before deploy"** -> Twoją pierwszą myślą powinno być **Binary Authorization**.
- Pamiętaj o modelu **Atestatorów (Attestors)** – to one są odpowiedzialne za "podpisanie" obrazu po przejściu przez zaufany krok w pipeline.

Analiza i Podsumowanie (AI)

Kwestia bezpieczeństwa łańcucha dostaw oprogramowania (Software Supply Chain Security) jest kluczowa na egzaminie Professional Cloud DevOps Engineer. Pytanie to testuje wiedzę o tym, jak technicznie uniemożliwić uruchomienie nieautoryzowanego kodu w środowisku GKE.

Kluczowe zagadnienia:

  • Policy Enforcement: Użycie Binary Authorization do blokowania niepodpisanych obrazów.
  • Integracja CI/CD: Pipeline jako zaufane źródło atestów.
  • GKE Admission Control: Moment, w którym następuje weryfikacja (przed utworzeniem podów).

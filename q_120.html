Question 120 / 201

GKE Kubernetes

You have an application that runs in Google Kubernetes Engine (GKE). The application consists of several microservices that are deployed to GKE by using Deployments and Services. One of the microservices is experiencing an issue where a Pod returns 403 errors after the Pod has been running for more than five hours. Your development team is working on a solution, but the issue will not be resolved for a month. You need to ensure continued operations until the microservice is fixed. You want to follow Google-recommended practices and use the fewest number of steps.

What should you do?

  • A. Create a cron job to terminate any Pods that have been running for more than five hours.
  • B. Add a HTTP liveness probe to the microservice's deployment.
  • C. Monitor the Pods, and terminate any Pods that have been running for more than five hours.
  • D. Configure an alert to notify you whenever a Pod returns 403 errors.
Show Suggested Answer
Suggested Answer: B 
Odpowiedź: B

Wyjaśnienie:
Liveness probe jest mechanizmem w Kubernetes, który pozwala na monitorowanie stanu kontenera. Jeśli skonfigurujesz sondę typu HTTP (która np. sprawdza endpoint aplikacji), to w przypadku gdy aplikacja zacznie zwracać błędy (np. 403), sonda zgłosi awarię, a Kubernetes automatycznie zrestartuje Pod. Jest to zalecana metoda naprawy "w locie" dla niestabilnych mikroserwisów, wymagająca najmniej pracy (konfiguracja w YAML Deployment).

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Tworzenie dodatkowego cron joba do zarządzania cyklem życia podów to tzw. "toil" (ręczna praca operacyjna) i niepotrzebne zwiększanie złożoności zarządzania, podczas gdy k8s ma to wbudowane (probes).
- Opcja C: Ręczne monitorowanie i zabijanie podów przez człowieka jest całkowicie nieakceptowalne w środowiskach automatyzowanych CI/CD.
- Opcja D: Alertowanie poinformuje Cię o problemie, ale go nie naprawi (nie zapewni "continued operations").

Więcej informacji:
- Kubernetes: Configure Liveness, Readiness and Startup Probes

Analiza i Podsumowanie Dyskusji (AI)

Jeśli aplikacja w GKE staje się niestabilna po pewnym czasie, liveness probe to najszybszy i najbardziej "kubernetesowy" sposób na zapewnienie jej ciągłego działania poprzez automatyczne restarty.

💡 Wskazówki i Triki (Exam Tips)

  • Słowo klucz: "Continued operations" + "minimal number of steps" = szukaj wbudowanych mechanizmów Kubernetes, takich jak Probes.
  • Unikaj: Ręcznych skryptów, dodatkowych cron jobów do zadań, które Kubernetes potrafi zrobić natywnie.

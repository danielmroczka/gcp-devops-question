Question 24 / 201

Stackdriver

You currently store the virtual machine (VM) utilization logs in Stackdriver. You need to provide an easy-to-share interactive VM utilization dashboard that is updated in real time and contains information aggregated on a quarterly basis. You want to use Google Cloud Platform solutions.

What should you do?

  • A. 1. Export VM utilization logs from Stackdriver to BigQuery. 2. Create a dashboard in Data Studio. 3. Share the dashboard with your stakeholders.
  • B. 1. Export VM utilization logs from Stackdriver to Cloud Pub/Sub. 2. From Cloud Pub/Sub, send the logs to a SIEM system. 3. Build the dashboards in the SIEM system and share with your stakeholders.
  • C. 1. Export VM utilization logs from Stackdriver to BigQuery. 2. From BigQuery, export the logs to a CSV file. 3. Import the CSV file into Google Sheets. 4. Build a dashboard in Google Sheets and share it with your stakeholders.
  • D. 1. Export VM utilization logs from Stackdriver to a Cloud Storage bucket. 2. Enable the Cloud Storage API to pull the logs programmatically. 3. Build a custom data visualization application. 4. Display the pulled logs in a custom dashboard.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A.

Wyjaśnienie:
Poprawną odpowiedzią jest **A (1. Export VM utilization logs from Stackdriver to BigQuery. 2. Create a dashboard in Data Studio. 3. Share the dashboard with your stakeholders)**.

**Dlaczego A jest poprawne?**
To rozwiązanie wykorzystuje trzy potężne, natywne usługi GCP w sposób zautomatyzowany:
1.  **Cloud Logging (Stackdriver):** Gromadzi logi i metryki z maszyn VM.
2.  **BigQuery:** Dzięki mechanizmowi "Log Sink" (zlewozmywak logów), dane mogą być automatycznie przesyłane do BigQuery w czasie rzeczywistym. BigQuery idealnie nadaje się do przechowywania ogromnych ilości danych przez długi czas (np. kwartały) i pozwala na wykonywanie szybkich zapytań SQL w celu agregacji danych.
3.  **Looker Studio (dawniej Data Studio):** Jest to darmowe, chmurowe narzędzie do wizualizacji, które posiada natywny konektor do BigQuery. Pozwala na tworzenie interaktywnych, łatwych do udostępnienia dashboardów, które odświeżają się automatycznie.

**Dlaczego pozostałe opcje są błędne?**
*   **B. Export VM utilization logs... to a SIEM system:** Systemy SIEM (Security Information and Event Management) służą do analizy bezpieczeństwa i wykrywania zagrożeń, a nie do monitorowania wydajności i utylizacji zasobów. Ponadto, SIEM to często rozwiązanie zewnętrzne, a pytanie wymaga użycia rozwiązań GCP.
*   **C. Export the logs to a CSV file... Import into Google Sheets:** To podejście jest skrajnie nieefektywne. Po pierwsze, kwartalne logi z wielu maszyn VM z łatwością przekroczą limity wierszy w Google Sheets. Po drugie, ręczny eksport do CSV i import to klasyczny przykład "toil" (mozolnej, ręcznej pracy), którego należy unikać w DevOps. Nie zapewnia to również aktualizacji w czasie rzeczywistym.
*   **D. Build a custom data visualization application:** Budowanie własnej aplikacji tylko po to, by wyświetlić wykresy utylizacji VM, jest niepotrzebnym marnotrawstwem zasobów (zarówno czasu programistów, jak i kosztów utrzymania infrastruktury). W myśl zasady "Focus on what provides value", należy korzystać z gotowych narzędzi typu Managed Services (jak Looker Studio), zamiast tworzyć je od zera.

### 💡 Hity i triki (Hints & Tricks)
- Ścieżka **Logs -> BigQuery -> Looker Studio** to najczęstszy wzorzec analityczny w Google Cloud. Zapamiętaj tę kombinację dla pytań o raportowanie i długoterminową analizę logów.
- Pamiętaj, że standardowy okres retencji logów w Cloud Logging to 30 dni. Aby analizować dane kwartalne (90 dni), **musisz** je wyeksportować (np. do BigQuery lub Cloud Storage).

Analiza i Podsumowanie (AI)

Zadanie to sprawdza wiedzę na temat ekosystemu analitycznego Google Cloud. Jako DevOps Engineer musisz wiedzieć, jak dostarczać interesariuszom dane o infrastrukturze w sposób przejrzysty i bezobsługowy.

Kluczowe zagadnienia:

  • Log Retention: Świadomość limitów przechowywania danych w Cloud Logging.
  • Toil Reduction: Wybór zautomatyzowanych potoków danych zamiast manualnych procesów (CSV/Sheets).
  • Managed Services: Wykorzystanie gotowych narzędzi BI (Looker Studio) zamiast budowania własnych rozwiązań.

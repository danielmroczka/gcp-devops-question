Question 270 / 284

Your organization uses Cloud Run to deploy a containerized application. A new version of the application recently passed internal tests and now needs to be tested in production. You need to implement a configuration so that beta testers can test the application before you roll out the application to end users. What should you do?

  • A. Deploy the Cloud Run application to production, and direct 1% of traffic to the application.
  • B. Configure Google Cloud Armor to reject requests that originate from IP addresses outside of the testing team.
  • C. Deploy the container to a private VM instance on Compute Engine, and enable access for the testing team only.
  • D. Deploy the Cloud Run application to production with a revision tag and the "--no-traffic" option, and share the URL with the testing team.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
Opcja D jest najlepsza, ponieważ tagowanie rewizji (revision tag) z opcją `--no-traffic` pozwala wdrożyć nową wersję do środowiska produkcyjnego bez narażania jej na ruch od użytkowników końcowych. Google Cloud generuje unikalny adres URL dla tej konkretnej rewizji, który można udostępnić beta testerom w celu weryfikacji w rzeczywistym środowisku.

Wyjaśnienie błędnych odpowiedzi:
- A: Kierowanie nawet 1% ruchu produkcyjnego naraża użytkowników na potencjalne błędy w nowej wersji.
- B: Google Cloud Armor chroni przed atakami, nie służy do kontroli dostępu beta-testerów w ten sposób.
- C: Wdrażanie na VM (Compute Engine) nie testuje aplikacji w rzeczywistym środowisku Cloud Run.

Analiza i Podsumowanie Dyskusji (AI)

Testowanie w produkcji bez narażania użytkowników = Cloud Run revision tags + no traffic.

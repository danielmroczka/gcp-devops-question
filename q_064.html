Question 64 / 201

Stackdriver

You support a trading application written in Python and hosted on App Engine flexible environment. You want to customize the error information being sent to Stackdriver Error Reporting.

What should you do?

  • A. Install the Stackdriver Error Reporting library for Python, and then run your code on a Compute Engine VM.
  • B. Install the Stackdriver Error Reporting library for Python, and then run your code on Google Kubernetes Engine.
  • C. Install the Stackdriver Error Reporting library for Python, and then run your code on App Engine flexible environment.
  • D. Use the Stackdriver Error Reporting API to write errors from your application to ReportedErrorEvent, and then generate log entries with properly formatted error messages in Stackdriver Logging.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D.

Wyjaśnienie:
Poprawna odpowiedź to D. Chociaż biblioteki klienckie (opcja C) ułatwiają integrację, pytanie dotyczy **personalizacji** (customization) informacji o błędach. 

Dlaczego odpowiedź D jest najlepsza:
1. Pełna kontrola: Użycie API Error Reporting lub przesyłanie logów w formacie `ReportedErrorEvent` pozwala na dołączenie szczegółowych metadanych, takich jak kontekst użytkownika (User context), kontekst usługi (Service context) czy specyficzne informacje o żądaniu HTTP.
2. Elastyczność: Możesz sformatować logi w Cloud Logging tak, aby Error Reporting automatycznie je wyłapał i zinterpretował jako błędy strukturalne, co jest najbardziej elastycznym sposobem na przesyłanie niestandardowych danych w środowisku App Engine Flexible.

Analiza błędnych odpowiedzi:
- A i B: Proponują zmianę środowiska uruchomieniowego (Compute Engine, GKE), co jest niepotrzebne i nie rozwiązuje problemu personalizacji samej informacji o błędzie w Pythonie.
- C: Instalacja biblioteki to krok wstępny. Biblioteka "pod maską" i tak wysyła dane do API, ale odpowiedź D precyzyjniej wskazuje na mechanizm (`ReportedErrorEvent`), który jest kluczem do zaawansowanej personalizacji zgodnie ze specyfikacją Error Reporting.

Hity i triki (Exam Tips):
- Error Reporting automatycznie wykrywa błędy w logach, jeśli zawierają one "Stack Trace" (zrzut stosu).
- Jeśli chcesz dodać do błędu informację o konkretnym użytkowniku (user ID), musisz użyć struktury `context.user`.
- Zapamiętaj frazę `ReportedErrorEvent` – to oficjalna nazwa struktury JSON, której Error Reporting używa do identyfikacji szczegółów błędu w logach.

- [Error Reporting API reference](https://cloud.google.com/error-reporting/docs/reference/rest/v1beta1/projects.events/report)

Analiza i Podsumowanie Dyskusji (AI)

W środowisku App Engine Flexible, Error Reporting jest kluczowym elementem strategii "Observability". Standardowe logowanie `print()` lub `logging.error()` może wystarczyć do wykrycia błędu, ale profesjonalny DevOps Engineer dąży do wzbogacenia tych danych o kontekst biznesowy i techniczny, co skraca czas naprawy (MTTR).

💡 Wskazówki i Triki (Exam Tips)

  • W Pythonie na App Engine, Error Reporting biblioteka jest zazwyczaj najlepszym startem, ale na egzaminie szukaj słów kluczowych takich jak **JSON structure**, **ReportedErrorEvent** lub **API**, gdy mowa o zaawansowanej personalizacji.
  • Upewnij się, że Twoja usługa ma uprawnienia IAM `logging.logWriter` oraz `errorreporting.writer`.
  • Error Reporting grupuje błędy na podstawie ich podobieństwa – personalizacja pomaga uniknąć błędnego grupowania różnych problemów w jeden rekord.

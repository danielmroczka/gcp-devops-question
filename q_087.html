Question 87 / 201

Your company has a Google Cloud resource hierarchy with folders for production, test, and development. Your cyber security team needs to review your company's Google Cloud security posture to accelerate security issue identification and resolution. You need to centralize the logs generated by Google Cloud services from all projects only inside your production folder to allow for alerting and near-real time analysis.

What should you do?

  • A. Enable the Workflows API and route all the logs to Cloud Logging.
  • B. Create a central Cloud Monitoring workspace and attach all related projects.
  • C. Create an aggregated log sink associated with the production folder that uses a Pub/Sub topic as the destination.
  • D. Create an aggregated log sink associated with the production folder that uses a Cloud Logging bucket as the destination.
Show Suggested Answer
Suggested Answer: C 
Odpowiedź: C

Wyjaśnienie:
Wymaganie polega na scentralizowaniu logów z wielu projektów w jednym miejscu (folderze produkcyjnym) przy jednoczesnym zapewnieniu możliwości alertowania i analizy w czasie rzeczywistym.

- Opcja C (Poprawna): Log Sink pozwala na eksportowanie logów poza projekt (np. do Pub/Sub, BigQuery lub Cloud Storage). Użycie "agregowanego" log sinka (aggregated log sink) na poziomie folderu lub organizacji pozwala na zebranie wszystkich logów z projektów podrzędnych. Pub/Sub jest doskonałym miejscem docelowym dla "near-real time analysis" (analizy w czasie niemal rzeczywistym), ponieważ pozwala na łatwe podpięcie subskrybentów (np. Dataflow do analizy lub systemów alertujących).

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Workflows służą do orkiestracji procesów, a nie do centralnego zbierania i rutowania logów na poziomie całej infrastruktury folderów/projektów.
- Opcja B: Cloud Monitoring workspace pozwala na widoczność metryk (i części logów) z wielu projektów w jednym panelu, ale nie jest to mechanizm "centralizacji logów" w celach archiwizacji czy zaawansowanej analizy (do tego służy Log Sink + Log Bucket/BigQuery).
- Opcja D: Log bucket (Cloud Logging bucket) jest poprawną metodą przechowywania logów, ale Pub/Sub (w opcji C) lepiej wspiera wymaganie "near-real time analysis" i alertowania, gdyż pozwala na natychmiastowe przetwarzanie zdarzeń przez inne usługi GCP.

💡 Wskazówki i Triki (Exam Tips)

  • Złota zasada logowania: Jeśli potrzebujesz logów z całego folderu/organizacji, używaj Aggregated Log Sinks.
  • Real-time vs Storage: Pub/Sub jest idealny dla streamingu/analizy czasu rzeczywistego (triggering alerts/functions), podczas gdy BigQuery jest lepszy dla analityki historycznej, a GCS dla taniej archiwizacji.

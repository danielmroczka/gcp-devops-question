Question 71 / 201

GKE Kubernetes

You support a popular mobile game application deployed on Google Kubernetes Engine (GKE) across several Google Cloud regions. Each region has multiple Kubernetes clusters. You receive a report that none of the users in a specific region can connect to the application. You want to resolve the incident while following Site Reliability Engineering practices. What should you do first?

  • A. Reroute the user traffic from the affected region to other regions that don't report issues.
  • B. Use Stackdriver Monitoring to check for a spike in CPU or memory usage for the affected region.
  • C. Add an extra node pool that consists of high memory and high CPU machine type instances to the cluster.
  • D. Use Stackdriver Logging to filter on the clusters in the affected region, and inspect error messages in the logs.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
W SRE (Site Reliability Engineering), w przypadku wystąpienia incydentu o krytycznym znaczeniu, priorytetem jest "Mitigacja" (ograniczenie wpływu na użytkownika), a nie od razu "Diagnoza".

Dlaczego A jest poprawne:
- Najszybszą metodą przywrócenia dostępności dla użytkowników w systemach wieloregionalnych jest skierowanie ruchu do zdrowych regionów (load balancer/global routing). To minimalizuje MTTR (Mean Time To Recovery).

Dlaczego inne są błędne:
- B, D: Diagnoza (logi/monitoring) jest ważna, ale w pierwszej kolejności należy ograniczyć wpływ awarii na klientów. Jeśli wykonasz to przed mitigacją, użytkownicy będą odczuwać brak dostępu przez cały czas trwania diagnozy.
- C: Skalowanie klastra nie naprawi awarii całego regionu, jeśli przyczyna leży w warstwie sieciowej, konfiguracji lub usługach zewnętrznych.

Wskazówki (Tricks):
- SRE Motto: "Mitigate first, diagnose later". Zawsze wybieraj opcję, która najszybciej przywraca obsługę użytkowników (np. rerouting, rollback, failover).

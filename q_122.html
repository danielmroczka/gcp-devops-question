Question 122 / 201

You are building an application that runs on Cloud Run. The application needs to access a third-party API by using an API key. You need to determine a secure way to store and use the API key in your application by following Google-recommended practices.

What should you do?

  • A. Save the API key in Secret Manager as a secret. Reference the secret as an environment variable in the Cloud Run application.
  • B. Save the API key in Secret Manager as a secret key. Mount the secret key under the /sys/api_key directory, and decrypt the key in the Cloud Run application.
  • C. Save the API key in Cloud Key Management Service (Cloud KMS) as a key. Reference the key as an environment variable in the Cloud Run application.
  • D. Encrypt the API key by using Cloud Key Management Service (Cloud KMS), and pass the key to Cloud Run as an environment variable. Decrypt and use the key in Cloud Run.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
GCP zapewnia natywną integrację między Secret Manager a Cloud Run. Najprostszym i najbardziej bezpiecznym sposobem (zgodnym z Google Recommended Practices) jest przechowywanie sekretów w Secret Managerze i bezpośrednie mapowanie ich na zmienne środowiskowe lub wolumeny w definicji usługi Cloud Run.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja B: Choć montowanie jako wolumeny jest dopuszczalne, to "decrypt the key in the Cloud Run application" jest zbędne – Secret Manager zarządza bezpieczeństwem, a montowanie/mapowanie na zmienne środowiskowe robi to transparentnie.
- Opcje C i D: Cloud KMS służy do zarządzania kluczami szyfrującymi (szyfrowanie danych), a nie do przechowywania samych wartości sekretów (np. API keys). Używanie KMS do ręcznego szyfrowania sekretów przed wdrożeniem wprowadza niepotrzebną złożoność operacyjną.

Analiza i Podsumowanie Dyskusji (AI)

W GCP zawsze przechowuj sekrety (hasła, klucze API) w Secret Managerze, a nie w kodzie czy zmiennych środowiskowych z "czystym" tekstem.

💡 Wskazówki i Triki (Exam Tips)

  • Złota zasada: Secret Manager dla wartości (sekretów), KMS dla operacji kryptograficznych (szyfrowanie danych). Nigdy nie myl tych usług w pytaniach!

Question 179 / 201

You are troubleshooting a failed deployment in your CI/CD pipeline. The deployment logs indicate that the application container failed to start due to a missing environment variable. You need to identify the root cause and implement a solution within your CI/CD workflow to prevent this issue from recurring.

What should you do?

  • A. Use a canary deployment strategy.
  • B. Implement static code analysis in the CI pipeline.
  • C. Run integration tests in the CI pipeline.
  • D. Enable Cloud Audit Logs for the deployment.
Show Suggested Answer
Suggested Answer: C 
Odpowiedź: C

Wyjaśnienie:
Problem dotyczy aplikacji, która nie uruchamia się z powodu brakującej zmiennej środowiskowej.
1. Integration tests (Testy integracyjne) są kluczowe w potoku CI/CD, ponieważ weryfikują współpracę różnych komponentów systemu, w tym środowiska uruchomieniowego (np. obecność zmiennych środowiskowych). Dzięki nim wykrywamy takie błędy na etapie testów, przed deploymentem na produkcję.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Canary deployment polega na stopniowym wdrażaniu wersji na produkcję dla wybranych użytkowników. Jeśli kontener nie wstaje z powodu błędu konfiguracyjnego (brak zmiennej), canary również nie zadziała poprawnie – nie naprawi to problemu, jedynie ograniczy wpływ na użytkowników.
- Opcja B: Static code analysis (statyczna analiza kodu) analizuje kod źródłowy pod kątem błędów składniowych, naruszeń stylu lub luk bezpieczeństwa. Zazwyczaj nie sprawdza konfiguracji środowiska uruchomieniowego (zmienne środowiskowe), więc nie wykryłaby tego błędu.
- Opcja D: Cloud Audit Logs służy do monitorowania działań (kto, co, kiedy zrobił w GCP). Pozwala zdiagnozować, *dlaczego* coś się stało po fakcie, ale nie zapobiega wystąpieniu błędu konfiguracyjnego w kolejnych wdrożeniach.

Analiza i Podsumowanie Dyskusji (AI)

Błędy konfiguracyjne ("missing environment variable") to klasyczny problem infrastruktury. Testy integracyjne w CI pozwalają upewnić się, że aplikacja ma dostęp do wszystkich niezbędnych parametrów przed wejściem na produkcję.

💡 Wskazówki i Triki (Exam Tips)

  • CI = Testowanie: Jeśli w pytaniu jest problem z uruchomieniem aplikacji w CI/CD, zawsze szukaj odpowiedzi związanej z testami (integracyjne, smoke tests).
  • Rozróżniaj: Logowanie (Audit Logs) to diagnostyka, Testowanie to prewencja.

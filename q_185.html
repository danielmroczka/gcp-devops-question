Question 185 / 201

You are configuring a CI pipeline. The build step for your CI pipeline integration testing requires access to APIs inside your private VPC network. Your security team requires that you do not expose API traffic publicly. You need to implement a solution that minimizes management overhead.

What should you do?

  • A. Use Cloud Build private pools to connect to the private VPC.
  • B. Use Cloud Build to create a Compute Engine instance in the private VPC. Run the integration tests on the VM by using a startup script.
  • C. Use Cloud Build as a pipeline runner. Configure a cross-region internal Application Load Balancer for API access.
  • D. Use Cloud Build as a pipeline runner. Configure a global external Application Load Balancer with a Google Cloud Armor policy for API access.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
Wymagania pytania to dostęp do prywatnych zasobów w VPC przez CI/CD (Cloud Build) przy zachowaniu bezpieczeństwa (brak ekspozycji publicznej) i minimalizacji zarządzania (management overhead).

Dlaczego poprawna jest odpowiedź A:
- A. Use Cloud Build private pools to connect to the private VPC: Prywatne pule (Private Pools) w Cloud Build pozwalają na uruchamianie zadań wewnątrz Twojej sieci VPC. Dzięki temu mają one bezpośredni, bezpieczny dostęp do prywatnych adresów IP w Twojej sieci bez konieczności wystawiania ich do internetu. Jest to rozwiązanie natywne ("managed") i wymaga minimalnego wysiłku konfiguracyjnego.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja B: Tworzenie maszyn wirtualnych (VM) przez Cloud Build do każdego zadania testowego wprowadza duży narzut operacyjny (zarządzanie obrazami, skryptami startowymi, cyklem życia VM), co jest sprzeczne z celem minimalizacji management overhead.
- Opcja C i D: Wystawianie load balancera (nawet wewnętrznego) nie jest optymalnym rozwiązaniem dla CI/CD. Wprowadza dodatkowe komponenty sieciowe do zarządzania, a zadanie CI/CD powinno po prostu "być" wewnątrz sieci, aby mieć do niej dostęp, a nie łączyć się przez load balancery. Dodatkowo opcja D proponuje zewnętrzny load balancer, co narusza wymóg bezpieczeństwa (brak ekspozycji publicznej).

Analiza i Podsumowanie Dyskusji (AI)

Kiedy w GCP potrzebujesz, aby narzędzie SaaS (takie jak Cloud Build) miało dostęp do zasobów w Twojej prywatnej sieci VPC, zawsze szukaj rozwiązań typu Private Pool lub VPC Connector.

💡 Wskazówki i Triki (Exam Tips)

  • Private Pool = Prywatna sieć: Jeśli pytanie dotyczy Cloud Build i potrzebujesz dostępu do prywatnych IP w VPC – odpowiedź to zawsze Private Pool.
  • Unikaj ręcznego zarządzania: Jeśli rozwiązanie wymaga tworzenia/zarządzania własnymi VM, zazwyczaj nie jest to najlepsza odpowiedź w GCP.

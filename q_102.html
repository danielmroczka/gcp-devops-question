Question 102 / 201

GKE Kubernetes

Your company runs an ecommerce website built with JVM-based applications and microservice architecture in Google Kubernetes Engine (GKE). The application load increases during the day and decreases during the night. Your operations team has configured the application to run enough Pods to handle the evening peak load. You want to automate scaling by only running enough Pods and nodes for the load.

What should you do?

  • A. Configure the Vertical Pod Autoscaler, but keep the node pool size static.
  • B. Configure the Vertical Pod Autoscaler, and enable the cluster autoscaler.
  • C. Configure the Horizontal Pod Autoscaler, but keep the node pool size static.
  • D. Configure the Horizontal Pod Autoscaler, and enable the cluster autoscaler.
Show Suggested Answer
Suggested Answer: D 
Odpowiedź: D

Wyjaśnienie:
Twoim celem jest skalowanie zarówno liczby Podów (aby obsługiwać zmienny ruch), jak i liczby węzłów (aby te Pody miały gdzie działać).

Dlaczego D jest poprawną odpowiedzią:
- Horizontal Pod Autoscaler (HPA): Automatycznie skaluje liczbę replik Podów w zależności od zapotrzebowania (np. użycie CPU/RAM).
- Cluster Autoscaler (CA): Automatycznie skaluje liczbę węzłów w klastrze, gdy Pody nie mogą zostać uruchomione (brak zasobów) lub gdy węzły są niedostatecznie wykorzystane. To połączenie idealnie realizuje założenie: "tylko wystarczająca liczba Podów i węzłów".

Wyjaśnienie niepoprawnych odpowiedzi:
- A i C: Jeśli ograniczysz się tylko do skalowania Podów (HPA) bez skalowania węzłów, to w sytuacji dużego ruchu Pody nie będą miały gdzie się uruchomić, jeśli węzły osiągną limit zasobów. Jeśli ograniczysz się tylko do VPA (skalowanie w górę/dół zasobów pojedynczego Poda), również nie rozwiążesz problemu zmiennej liczby Podów przy zmiennym ruchu.
- B: VPA zmienia zasoby (requesty/limity) pojedynczych Podów. W środowiskach o zmiennym natężeniu ruchu (typowy ecommerce) znacznie lepiej sprawdza się horyzontalne skalowanie (dodawanie/usuwanie Podów - HPA), podczas gdy VPA jest używane do optymalizacji zasobów stałych Podów.

Więcej informacji:
- Google Cloud: HPA
- Google Cloud: Cluster Autoscaler

Analiza i Podsumowanie Dyskusji (AI)

Skalowanie w GKE to zazwyczaj duet: HPA (dla Podów) + Cluster Autoscaler (dla węzłów).

💡 Wskazówki i Triki (Exam Tips)

  • Zawsze myśl dwupoziomowo w Kubernetes: Skalowanie aplikacji (Pody) i skalowanie infrastruktury (węzły).
  • Jeśli aplikacja ma zmienne obciążenie, Horizontal Pod Autoscaler jest zawsze pierwszym wyborem.

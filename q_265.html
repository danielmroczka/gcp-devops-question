Question 265 / 284

You have an application served by a single Compute Engine instance in one region. The VM occasionally shuts down and disrupts end user workflows. You need a quick and reliable solution that notifies you when there are VM shutdowns. What should you do?

  • A. Use the Logs Explorer to create a log-based alert for VM instances with the v1.compute.instances.stop payload method name.
  • B. Export the logs to BigQuery and run hourly scheduled queries to identify VM instances with the v1.compute.instances.stop payload method name.
  • C. Update the application code to identify situations when the VM is close to shutting down, and send a notification.
  • D. Configure Cloud Scheduler to run a randomized health check on the VM with a maximum time gap of one hour.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
Log-based alerts (alerty oparte na logach) w Cloud Monitoring pozwalają na błyskawiczne reagowanie na zdarzenia zarejestrowane w Cloud Logging. VM shutdown (zdarzenie typu `compute.instances.stop`) jest logowane przez Google Cloud, więc alert oparty na tym logu jest najszybszym i najbardziej niezawodnym sposobem na powiadomienie administratora.

Wyjaśnienie błędnych odpowiedzi:
- B: BigQuery jest świetne do analizy historycznej, ale zbyt wolne na szybkie powiadomienia (analiza co godzinę jest niewystarczająca).
- C: Kod aplikacji nie zawsze może przewidzieć niespodziewane wyłączenie VM (np. przez administratora lub błąd systemu).
- D: Cloud Scheduler nie służy do monitorowania stanu VM; zdrowie instancji lepiej sprawdzać za pomocą wbudowanych mechanizmów GCP.

Analiza i Podsumowanie Dyskusji (AI)

Kluczem do pytania jest "szybkie i niezawodne powiadomienie".

💡 Wskazówki i Triki (Exam Tips)

  • Monitoring: Log-based alerts to najszybsza ścieżka dla zdarzeń auditowych.

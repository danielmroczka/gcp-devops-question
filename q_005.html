Question 5 / 201

Logging Stackdriver SLO

You are running an application in a virtual machine (VM) using a custom Debian image. The image has the Stackdriver Logging agent installed. The VM has the cloud-platform scope. The application is logging information via syslog. You want to use Stackdriver Logging in the Google Cloud Platform Console to visualize the logs. You notice that syslog is not showing up in the "All logs" dropdown list of the Logs Viewer.

What is the first thing you should do?

  • A. Look for the agent's test log entry in the Logs Viewer.
  • B. Install the most recent version of the Stackdriver agent.
  • C. Verify the VM service account access scope includes the monitoring.write scope.
  • D. SSH to the VM and execute the following commands on your VM: ps ax | grep fluentd.
Show Suggested Answer
Suggested Answer: D 
Poprawna odpowiedź: D.

Wyjaśnienie:
Przy rozwiązywaniu problemów (troubleshooting) z brakującymi danymi w chmurze, pierwszą zasadą jest weryfikacja stanu źródła. Agent Cloud Logging (dawniej Stackdriver) wykorzystuje pod spodem proces `fluentd` do zbierania, przetwarzania i wysyłania logów. Jeśli w Logs Viewer nie widzisz strumienia "syslog", najbardziej prawdopodobną przyczyną jest to, że agent na maszynie wirtualnej przestał działać lub w ogóle się nie uruchomił. Sprawdzenie listy procesów za pomocą `ps ax | grep fluentd` pozwala natychmiast potwierdzić, czy usługa jest aktywna.

Dlaczego pozostałe odpowiedzi są błędne:
A. Szukanie logów testowych w konsoli jest krokiem wtórnym. Jeśli agent nie działa na VM (co sprawdzamy w punkcie D), to żadne logi testowe ani produkcyjne i tak nie pojawią się w Logs Viewer.
B. Aktualizacja agenta bez wcześniejszej diagnozy ("czy w ogóle działa?") jest nieefektywnym działaniem (tzw. "shooting in the dark"). Może to naprawić problem przypadkiem, ale nie jest to poprawna metodologia SRE.
C. W treści pytania wspomniano, że VM ma zakres (scope) `cloud-platform`. Jest to najszerszy możliwy zakres, który domyślnie zawiera uprawnienia do zapisu logów i metryk. Sprawdzanie tego jest mniej priorytetowe niż weryfikacja działania samego procesu na systemie operacyjnym.

Analiza i Podsumowanie Dyskusji (AI)

Pytanie to testuje Twoje umiejętności praktycznego troubleshootingu w środowisku hybrydowym (OS + Cloud). Kluczem jest znajomość komponentów składowych agentów operacyjnych Google Cloud.

💡 Hity i triki (Exam Tips)

  • Cloud Logging Agent bazuje na Fluentd.
  • Cloud Monitoring Agent bazuje na Collectd. (W nowym Ops Agent te dwa procesy są połączone, ale na egzaminie często pojawiają się jeszcze jako osobne byty).
  • Access Scopes vs IAM Roles: Nawet jeśli masz rolę Editor w IAM, VM potrzebuje odpowiedniego Scope (np. `cloud-platform` lub `logging.write`), aby móc wysyłać dane. W pytaniu scope był poprawny.
  • Jeśli agent działa (`ps` zwraca wynik), kolejnym krokiem byłoby sprawdzenie pliku logów samego agenta: `/var/log/google-fluentd/google-fluentd.log`.

Question 279 / 284

Your organization runs many builds on Google Cloud daily. You need to ensure that VMs do not have public IP addresses and secure the build machines against data exfiltration. You want to use Google-recommended practices to create a customizable, easily-managed solution for your builds that can scale to the demands of your organization. What should you do?

  • A. Implement private pools in Cloud Build with VPC Service Controls.
  • B. Run and configure the builds in a default pool in Cloud Build for required privacy.
  • C. Create a build environment by using Compute Engine VMs in a custom VPC. Use Jenkins to run the builds.
  • D. Create a build environment by using Compute Engine Spot VM instances in a custom VPC. Use Jenkins to run the builds.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A

Wyjaśnienie:
Cloud Build Private Pools pozwalają na uruchamianie zadań budowania wewnątrz Twojej własnej VPC (bez publicznego IP), co zapewnia izolację sieciową. VPC Service Controls dodają dodatkową warstwę ochrony przed eksfiltracją danych, ograniczając dostęp do usług Google Cloud z tych pul.

Wyjaśnienie błędnych odpowiedzi:
- B: Default pool w Cloud Build używa publicznych IP i nie jest w pełni konfigurowalny pod względem izolacji sieciowej.
- C, D: Zarządzanie Jenkins na Compute Engine to ogromne "toil" (nakład pracy), którego DevOps powinien unikać, wybierając usługi zarządzane (managed services).

Analiza i Podsumowanie Dyskusji (AI)

Secure builds (Private IPs, no data exfil) = Cloud Build Private Pools + VPC SC.

💡 Wskazówki i Triki (Exam Tips)

  • Isolated builds = Cloud Build Private Pools.

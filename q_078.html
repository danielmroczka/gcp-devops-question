Question 78 / 201

Logging Stackdriver

You are running an application on Compute Engine and collecting logs through Stackdriver. You discover that some personally identifiable information (PII) is leaking into certain log entry fields. All PII entries begin with the text userinfo. You want to capture these log entries in a secure location for later review and prevent them from leaking to Stackdriver Logging. What should you do?

  • A. Create a basic log filter matching userinfo, and then configure a log export in the Stackdriver console with Cloud Storage as a sink.
  • B. Use a Fluentd filter plugin with the Stackdriver Agent to remove log entries containing userinfo, and then copy the entries to a Cloud Storage bucket.
  • C. Create an advanced log filter matching userinfo, configure a log export in the Stackdriver console with Cloud Storage as a sink, and then configure a log exclusion with userinfo as a filter.
  • D. Use a Fluentd filter plugin with the Stackdriver Agent to remove log entries containing userinfo, create an advanced log filter matching userinfo, and then configure a log export in the Stackdriver console with Cloud Storage as a sink.
Show Suggested Answer
Suggested Answer: C 
Odpowiedź: C

Wyjaśnienie:
Poprawna odpowiedź to C. 

Prawidłowe podejście w Google Cloud Logging, gdy musimy zachować dane PII, ale nie chcemy, aby były one widoczne w głównym panelu Logging (naruszając politykę retencji lub dostępności danych), to:
1. Użycie Log Sinks (eksport do GCS): Sinks przechwytują wszystkie logi (zanim zostaną wykluczone) i eksportują je do bezpiecznego zasobnika Google Cloud Storage (GCS). W GCS możemy skonfigurować bardziej rygorystyczne polityki dostępu (IAM) oraz retencji (Bucket Lock).
2. Użycie Log Exclusions: Wykluczenia w Cloud Logging służą do usuwania (lub filtrowania) logów z indeksowania i przechowywania w głównym interfejsie Cloud Logging. Wykluczone logi nie są płatne i nie zajmują miejsca w logach, ale eksport (sink) nadal je przechwytuje.

Dlaczego inne odpowiedzi są błędne:
- A: Brak Log Exclusion spowoduje, że dane PII nadal będą przechowywane w Cloud Logging, co narusza bezpieczeństwo i zgodność z RODO/GDPR.
- B: Fluentd może być użyty do manipulacji logami, ale wymaga utrzymywania dodatkowego oprogramowania na każdej maszynie (agent), co jest mniej wydajne i trudniejsze w zarządzaniu niż natywne funkcje Logging ("Cloud-native approach").
- D: Łączy nadmiarowe kroki (Fluentd + Log Exclusions), co tworzy niepotrzebny "Toil" (pracę ręczną/złożoność operacyjną), podczas gdy natywne Log Sinks wystarczają do tego zadania.

Hity i triki:
- Pamiętaj, że Log Sinks przetwarzają logi w kolejności ich przychodzenia, niezależnie od wykluczeń. Jeśli wyeksportujesz logi do GCS, będą tam bezpiecznie zapisane.
- Używaj "Data Access Logs" oraz wykluczeń, aby zarządzać kosztami i zgodnością (compliance).

Question 144 / 201

You have an application that runs on Cloud Run. You want to use live production traffic to test a new version of the application, while you let the quality assurance team perform manual testing. You want to limit the potential impact of any issues while testing the new version, and you must be able to roll back to a previous version of the application if needed.

How should you deploy the new version? (Choose two.)

  • A. Deploy the application as a new Cloud Run service.
  • B. Deploy a new Cloud Run revision with a tag and use the --no-traffic option.
  • C. Deploy a new Cloud Run revision without a tag and use the --no-traffic option.
  • D. Deploy the new application version and use the --no-traffic option. Route production traffic to the revision's URL.
  • E. Deploy the new application version, and split traffic to the new version.
Show Suggested Answer
Suggested Answer: B, E 
Odpowiedź: B, E

Wyjaśnienie:
To zadanie wymaga spełnienia dwóch celów: umożliwienia zespołowi QA testów manualnych oraz przetestowania nowej wersji na żywym ruchu produkcyjnym (Canary testing).

1. Opcja B (Tagi dla QA): Użycie flagi --tag podczas wdrażania z --no-traffic pozwala na utworzenie unikalnego, stabilnego adresu URL dla konkretnej rewizji (np. https://tag---service-url). Dzięki temu zespół QA może testować tę konkretną wersję w izolacji, zanim trafi ona do użytkowników.
2. Opcja E (Live Traffic): Aby przetestować nową wersję na "żywym ruchu" (zgodnie z wymaganiem "use live production traffic"), należy zastosować podział ruchu (traffic splitting). Pozwala to skierować niewielki procent (np. 1-5%) użytkowników do nowej wersji, co ogranicza potencjalny wpływ błędów i pozwala na natychmiastowy rollback.

Wyjaśnienie niepoprawnych odpowiedzi:
- Opcja A: Tworzenie osobnego serwisu Cloud Run dla każdej wersji jest nieefektywne i utrudnia płynne przełączanie ruchu (canary/rollback).
- Opcja C: Wdrożenie bez tagu sprawia, że dostęp dla QA jest utrudniony, ponieważ każda nowa rewizja otrzymuje losowy identyfikator, zamiast czytelnego i stałego adresu URL zapewnianego przez tag.
- Opcja D: Routing ruchu produkcyjnego bezpośrednio do URL-a rewizji nie jest zalecaną praktyką w Cloud Run. Wbudowany mechanizm "traffic splitting" (Opcja E) jest bezpieczniejszy i łatwiejszy w zarządzaniu.

Analiza i Podsumowanie Dyskusji (AI)

W Cloud Run kluczem do bezpiecznego wdrażania jest połączenie tagów (dla testów wewnętrznych) oraz podziału ruchu (dla testów na produkcji / canary).

💡 Wskazówki i Triki (Exam Tips)

  • --tag: Tworzy dedykowany URL https://TAG---SERVICE-URL. Idealne dla QA.
  • Traffic Splitting: Używaj, gdy pytanie wspomina o "live production traffic" lub "limiting impact" (Canary release).
  • Rollback: W Cloud Run rollback to po prostu ustawienie 100% ruchu na poprzednią, stabilną rewizję.

Question 55 / 201

Your organization recently adopted a container-based workflow for application development. Your team develops numerous applications that are deployed continuously through an automated build pipeline to the production environment. A recent security audit alerted your team that the code pushed to production could contain vulnerabilities and that the existing tooling around virtual machine (VM) vulnerabilities no longer applies to the containerized environment. You need to ensure the security and patch level of all code running through the pipeline. What should you do?

  • A. Set up Container Analysis to scan and report Common Vulnerabilities and Exposures.
  • B. Configure the containers in the build pipeline to always update themselves before release.
  • C. Reconfigure the existing operating system vulnerability software to exist inside the container.
  • D. Implement static code analysis tooling against the Docker files used to create the containers.
Show Suggested Answer
Suggested Answer: A 
Odpowiedź: A.

Wyjaśnienie:
Poprawna odpowiedź to A. Container Analysis jest natywną usługą GCP, która automatycznie skanuje obrazy kontenerów (przechowywane w Artifact Registry lub Container Registry) pod kątem znanych luk bezpieczeństwa (CVE - Common Vulnerabilities and Exposures). W środowisku kontenerowym, gdzie procesy CI/CD są zautomatyzowane, włączenie Container Analysis jest kluczowym elementem "shift-left security" i zapewnia, że obrazy z krytycznymi podatnościami nie trafią do produkcji.

Dlaczego inne odpowiedzi są błędne:
- B: "Samouaktualnianie" kontenerów w trakcie działania (runtime) jest anty-wzorcem. Kontenery powinny być niezmienne (immutable). Aktualizacje powinny być wprowadzane poprzez budowę nowego obrazu, skanowanie go i ponowne wdrożenie.
- C: Narzędzia do skanowania OS (typu agent na maszynie) nie mają wglądu w warstwy obrazu kontenera ani w biblioteki aplikacji zamknięte wewnątrz kontenera.
- D: Statyczna analiza plików Dockerfile (np. pod kątem best practices) nie sprawdza samych bibliotek i binariów zainstalowanych wewnątrz obrazu (tzw. "base image vulnerabilities"). Tylko Container Analysis skanuje rzeczywistą zawartość binarnego obrazu.

Analiza i Podsumowanie Dyskusji (AI)

W GCP, bezpieczeństwo kontenerów opiera się na Container Analysis, która zapewnia skanowanie obrazów w czasie rzeczywistym i w pipeline CI/CD.

Question 11 / 201

GKE Kubernetes

You support the backend of a mobile phone game that runs on a Google Kubernetes Engine (GKE) cluster. The application is serving HTTP requests from users. You need to implement a solution that will reduce the network cost.

What should you do?

  • A. Configure the VPC as a Shared VPC Host project.
  • B. Configure your network services on the Standard Tier.
  • C. Configure your Kubernetes cluster as a Private Cluster.
  • D. Configure a Google Cloud HTTP Load Balancer as Ingress.
Show Suggested Answer
Suggested Answer: B 
Odpowiedź: B.

Wyjaśnienie:
Google Cloud Platform oferuje dwie warstwy usług sieciowych (Network Service Tiers), które różnią się sposobem przesyłania ruchu między zasobami w chmurze a użytkownikami w internecie.

Dlaczego odpowiedź B jest poprawna:
Warstwa Standardowa (Standard Tier) kieruje ruch z GCP do Internetu przez publiczną sieć tranzytową (ISP), zamiast korzystać z globalnej sieci szkieletowej Google. Jest to rozwiązanie znacznie tańsze niż warstwa Premium, co czyni je idealnym wyborem w sytuacji, gdy głównym celem jest redukcja kosztów sieciowych ("reduce the network cost"). Wydajność w Standard Tier jest porównywalna z innymi dostawcami chmurowymi, ale niższa niż w Premium Tier Google.

Dlaczego pozostałe opcje są błędne:
A. Współdzielony VPC (Shared VPC) służy do zarządzania siecią w wielu projektach z poziomu jednego projektu hosta. Poprawia to bezpieczeństwo i spójność konfiguracji, ale samo w sobie nie zmniejsza kosztów ruchu wychodzącego (egress).
C. Klaster prywatny (Private Cluster) w GKE polega na tym, że węzły (nodes) nie posiadają publicznych adresów IP. Zwiększa to bezpieczeństwo (izolacja sieciowa), ale nie wpływa bezpośrednio na koszty transferu danych do użytkowników mobilnych.
D. Google Cloud HTTP Load Balancer używany jako Ingress jest bardzo wydajnym rozwiązaniem, ale domyślnie działa w warstwie Premium. Samo wdrożenie Load Balancera bez zmiany warstwy sieciowej na Standard nie spowoduje obniżenia kosztów, a może je nawet zwiększyć ze względu na opłaty za reguły przekierowania i przetworzone dane.

Hity i triki:
- Zapamiętaj: Premium Tier = Globalna sieć Google (szybciej, drożej). Standard Tier = Publiczny Internet (taniej).
- Ruch wewnątrz regionu jest zazwyczaj darmowy lub bardzo tani. Koszty generuje ruch wychodzący do Internetu (Egress).
- Cloud CDN (powiązany z HTTP Load Balancer) również może obniżyć koszty sieciowe dzięki cache'owaniu treści, ale Standard Tier jest najbardziej bezpośrednią odpowiedzią na pytanie o ogólne koszty sieciowe.

Przydatne linki:
- https://cloud.google.com/network-tiers/docs/overview
- https://cloud.google.com/network-tiers/docs/using-standard-tier

Analiza i Podsumowanie Dyskusji (AI)

W pytaniach o koszty sieciowe na egzaminie GCP, Network Service Tiers są najczęstszym punktem wyboru. Wybór między Premium a Standard to klasyczny balans między wydajnością a ceną.

💡 Wskazówki i Triki (Exam Tips)

  • Standard Tier: Ruch wychodzi z sieci Google tak szybko, jak to możliwe (Hot Potato Routing).
  • Premium Tier: Ruch podróżuje siecią Google tak blisko użytkownika, jak to możliwe (Cold Potato Routing).
  • Dla aplikacji mobilnych, gdzie opóźnienia mogą być tolerowane w zamian za niższe koszty, Standard Tier jest logicznym wyborem.
